## 목표와 인수 기준

회원이 품절 상품을 신청하면 확정 재입고로 다시 판매 가능해졌을 때 기존 알림함에서 한 번 안내한다. 알림은 재고 예약이나 구매 가능 시점을 보장하지 않는다. 외부 발송, 자동 재신청과 운영 활성화는 후속 범위다.

| 작업 항목 | 구현 범위 | 인수 기준 |
| --- | --- | --- |
| 신청·취소 | 상품 상세에서 본인 상태를 조회하고 품절 상품을 신청·취소 | 회원·상품별 활성 신청 한 건. 로그인 복귀는 조회만 수행하고 신청 시점에 품절 여부를 다시 확인 |
| 확정 재입고 감지 | 관리자 수량 추가 및 검수 적합 재입고 후 가용 재고 0→양수와 판매 가능 전환 감지 | 예약 해제, 판매 상태만 변경, 검수 불합격, 트랜잭션 롤백은 알림 생성 대상에서 제외 |
| 회원 알림함 | 주문·문의 알림과 함께 읽음·미읽음 수, 대상 상품 상세 연결 | 신청당 최대 한 건 게시. 게시 전에 다시 품절되거나 판매 중지된 경우 다음 확정 재입고 대기 |
| 운영과 장애 복구 | 기본 비활성, 기존 운영자 실패 조회·재시도와 별도 게시 트랜잭션 | 재시작·작업자 경합·반복 재시도에도 중복 게시 없이 복구. 게시 실패 시에도 재고 트랜잭션 결과 유지 |

## 화면과 API

| API | 동작 |
| --- | --- |
| `GET /api/restock-subscriptions/{productId}` | 세션 회원의 해당 상품 신청 상태와 신청 가능 여부를 반환. 내부 재고 수량과 다른 회원의 신청은 응답에 포함하지 않음 |
| `PUT /api/restock-subscriptions/{productId}` | 현재 화면에서 상품이 품절인 경우에만 신청. 이미 활성 신청이면 기존 신청을 반환. 새 신청 시 상품 상태가 바뀌었으면 409로 갱신 안내 |
| `DELETE /api/restock-subscriptions/{productId}` | 본인의 미게시 신청을 취소하며 반복 요청은 같은 결과. 게시가 먼저 확정된 알림은 읽음 상태와 이력을 유지 |

회원 식별은 서버 세션에서 얻고 기존 공통 응답·예외·CSRF 규칙을 사용한다. 회원 조회와 쓰기 응답은 캐시하지 않는다. 미인증 요청은 401, 존재하지 않거나 공개되지 않는 상품은 같은 404로 처리한다. 알림 신청 기능이 중단된 동안에도 현재 상태와 취소를 계속 사용할 수 있으며, 기능이 비활성이면 새 신청은 503으로 안내한다. 공개 상품 상세 응답은 기능이 켜졌을 때만 `restockNotificationEnabled: true`를 제공하며 브라우저에서 비회원 진입 안내에 사용한다. 상품 상세는 요청 성공 후에만 버튼 상태를 바꾸고, 로그인 복귀 경로에는 검증된 상품 식별자만 전달한다. 계정 전환과 페이지 이탈 시 이전 요청의 응답은 버린다.

기존 알림 API는 `PRODUCT_RESTOCKED`에만 `productId`를 십진 문자열로 반환한다. 기존 주문·문의 응답 형태와 권한은 유지한다. 회원은 상품 상세로 이동해 현재 상태를 확인한다. 링크 이동만으로 자동 읽음·신청·구매를 실행하지 않는다.

## 저장과 게시

- V18에 신청과 확정 재입고 이벤트를 저장한다. 적용된 V1~V17과 기존 주문·문의 알림 데이터는 보존한다. 개별 신청 ID를 기준으로 게시 유일성을 보장하고, 게시 후 다음 품절에 새 신청 ID를 발급한다.
- 상품 행 잠금 안에서 신청의 품절 상태 및 최신 재입고 순서를 확인한다. 관리자 재고 추가와 검수 적합 재입고에서만 해당 변경의 트랜잭션에 확정 이벤트를 기록한다. 신청 이전 이벤트는 사용하지 않는다.
- 판매 가능 상태가 끊겼다가 돌아오면 판매 가능 구간을 새로 식별한다. 예약 해제처럼 제외된 경로는 구매 가능 여부를 바꿀 수 있지만 확정 재입고 이벤트를 기록하지 않는다. 작업자는 이력의 확정 이벤트가 현재 판매 가능 구간에 속하는지, 신청이 여전히 활성인지 게시 트랜잭션에서 확인한다. 중간에 다시 품절되거나 판매 중지됐으면 알림을 게시하지 않고 다음 확정 이벤트를 기다린다.
- `notifications.enabled`와 별도 `notifications.restock.enabled`가 모두 켜져야 게시한다. 관리자 설정에서 UTC 시작 시각을 지정한다. 확정 시각이 기준 이상인 커밋만 처리하며 비활성 동안의 신청은 보존한다. 기존 제한 배치와 최대 3회 자동 시도, 운영자 개별 재시도를 사용한다. 재시도도 신청과 이벤트 상태를 재검사한다.
