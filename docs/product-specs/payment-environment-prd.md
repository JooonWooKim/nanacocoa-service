# 결제 환경 분리와 모의 PG 검증 PRD

상태: 구현됨 · 출시 PRD PAY 1단계 · 이슈 #16

## 목표와 범위

로컬·테스트·기본 Compose 실행이 실제 결제 제공자에 요청하지 않게 한다.
운영 프로필과 명시적 활성화를 동시에 사용하고, 운영용 클라이언트 키와
시크릿 키 및 제공자 주소가 유효할 때만 실제 Toss 연동을 구성한다.
복구 스케줄러는 결제 활성화와 스케줄러 활성화가 모두 필요하다.

주문 제출 멱등성, 운영 미확정 거래 화면, RETURN 연동, 구매자 브라우저
종단 검증은 PAY 후속 범위다. 이 단계는 주문, 재고·결제 상태 전이,
스키마를 바꾸지 않는다.

## API와 화면

- 기존 인증된 `GET /api/payments/client-config`는 활성 환경에서 공개용
  클라이언트 키만 반환한다. 비활성 환경은 기존 503 오류를 반환하며
  checkout은 주문 생성과 SDK 로딩 전에 결제 불가를 안내한다.
- 기존 승인·취소 POST는 비활성 환경에서 잠금·저장·외부 호출 전에 503으로
  종료한다. 기존 결제 조회와 주문 조회는 계속 가능하다.
- 활성화를 잘못 구성하면 애플리케이션 시작을 거부한다. 설정 오류에는
  키, 주소 입력값, 고객 정보가 포함되지 않는다.

## 인수 기준

- 기본 설정 및 Compose는 실 PG 호출과 예약된 복구를 차단한다.
- 운영 프로필 누락, 테스트 프로필, 키 누락·유형 불일치, 허용되지 않은
  제공자 주소는 활성화를 거부한다.
- 외부 통신 없는 HTTP 모의 PG로 승인·조회·취소의 요청 형식,
  멱등성 키 전달, 타임아웃 및 오류 분류를 검증한다.
- 기존 모의 PG 결제·재고 회귀와 `./scripts/harness check`를 실행한다.

운영 플래그와 비공개 설정 파일 반영 방법은
[결제 환경 운영 절차](../runbooks/payment-environment.md)를 따른다.
