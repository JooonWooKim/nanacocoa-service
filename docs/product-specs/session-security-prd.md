# SEC · 세션 보안 구현 PRD

| 항목 | 내용 |
| --- | --- |
| 우선순위 | P0 출시 전 |
| 대상 | 구매 회원, 운영자 |
| 상위 명세 | [커머스 출시 PRD](commerce-launch-prd.md#sec--세션-보안) |

## 목표와 범위

회원과 운영자가 가입·로그인, 주문·결제, 운영 작업을 안전하게 수행할 수 있게 한다.
서버는 상태 변경 요청에 CSRF 토큰을 요구하고, 로그인 이전에 사용한 세션 ID와
로그아웃으로 폐기한 세션 ID의 보호 자원 접근을 거부한다. PAY 환경 설정과 RETURN
기능은 상위 PRD 순서를 따른다. DB 스키마 변경은 없다.

## 서버와 API 계약

| 항목 | 요구사항 |
| --- | --- |
| `GET /api/auth/csrf` | 로그인 전후에 호출할 수 있다. 현재 세션의 토큰을 `SuccessMessage.data.headerName`과 `SuccessMessage.data.token`으로 제공하며 `Cache-Control: no-store`를 설정한다. |
| 상태 변경 요청 | Spring Security 기본 매처와 세션 기반 토큰 저장소를 사용한다. 가입·로그인·로그아웃, 마이페이지 본인 확인과 수정, 주문·결제, 상품 등록·재고·배송 관리에 적용한다. 무효·누락 토큰은 애플리케이션 로직 호출 전에 `403`과 `ErrorMessage`의 `CSRF_INVALID` 코드로 거부한다. 유효 토큰으로 요청하면 기존 인증·소유권·운영자 권한을 검증한다. |
| `POST /api/auth/login` | 자격 증명 검증 성공 시 `changeSessionId()`로 ID를 회전하고 이전 CSRF 토큰과 마이페이지 본인 확인 권한을 제거한 뒤 인증을 저장한다. 자격 증명이 틀리면 인증 상태와 세션 ID를 유지한다. |
| `POST /api/auth/logout` | 유효한 토큰을 확인한 뒤 인증을 지우고 세션을 폐기한다. 기존 익명 세션 응답을 반환한다. `GET /api/auth/logout`은 인증 상태 변경 없이 `405`를 반환한다. |

## 화면 동작

- 공통 `requestAuth`는 동일 출처에 상태 변경 요청을 보내기 직전에 새 토큰을
  조회해 발급된 헤더에 담는다. JSON, multipart 본문과 `Idempotency-Key`를
  그대로 전달한다. 배송 관리자 화면도 공통 경로에서 토큰을 가져온다.
- 토큰 조회에 실패하면 쓰기 요청을 중단한다. `CSRF_INVALID` 응답을 받으면 가능한
  입력을 유지하고 다시 제출할 수 있게 안내한다. 다음 제출에서 새 토큰을 조회하며
  쓰기 요청의 재시도는 사용자 행동으로 시작한다.
- 승인 콜백에서 세션이 만료되면 기존 로그인 복귀 경로를 사용한다. 세션이 유효한 CSRF
  오류에는 같은 승인 시도의 재시도를 제공한다. 승인 API는 주문 소유권·금액·결제 상태를
  다시 검증하며 기존 주문과 멱등성 키를 사용한다.

## 인수 기준

- 유효한 같은 세션 토큰으로 정상 쓰기가 성공한다. 누락·오류·다른 세션 토큰 및
  로그인 전 토큰은 거부된다. 거부된 요청의 회원·주문·결제·재고·배송 상태는 유지된다.
  유효 토큰이 있어도 일반 회원은 관리자 작업을 수행할 수 없다.
- 실제 HTTP 세션 쿠키로 로그인 전 ID와 로그아웃한 ID의 보호 자원 접근이 실패하고
  GET 로그아웃 뒤에는 인증이 유지됨을 확인한다. 재로그인 후 마이페이지 수정에는
  비밀번호 본인 확인을 다시 요구한다.
- 가입·로그인·로그아웃, 프로필 본인 확인·수정, 주문 생성·취소, 결제 승인, 상품
  이미지 등록, 재고·배송 변경을 회귀 검증한다. 모의 PG로 콜백 세션 만료와 재로그인
  복귀, 동일 시도의 주문·승인 중복 방지를 확인한다. 이미지 등록은 모의 저장소를 사용한다.
- 정확한 `NC-SEC-001/002/003` 예외를 해소한 증거와 `./scripts/harness test`,
  `./scripts/harness check` 결과를 기록한다. `NC-TEST-001`의 잔여 실패는 출시
  승인 전에 해소한다. 검증 증거에는 세션 ID, CSRF 토큰, 결제 키, 고객 정보를 남기지 않는다.
