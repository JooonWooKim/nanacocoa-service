## 목표와 범위

구매자는 이름과 카테고리로 상품을 찾고 목록을 페이지 단위로 살펴본다. 운영자는 상품을 한 카테고리에 배정하고 공개 필터의 순서와 노출을 조정한다. FAQ·문의 처리, 주문·출고·환불 알림 및 입고 알림은 후속 범위다.

| 작업 항목 | 구현 범위 | 인수 기준 |
| --- | --- | --- |
| 상품명 검색 | 상품명 일부 검색과 카테고리 조건을 서버에서 함께 적용 | 한글·영문 검색, 공백 처리, 실제 결과 없음과 실패 구분 |
| 필터·페이지 나누기 | 검색어·카테고리·페이지를 URL에 보관하고 24개씩 조회 | 공유·새로고침·뒤로 가기 복원, 조건 변경 시 첫 페이지, 늦은 응답 무시 |
| 카테고리 관리 | 운영자가 추가·이름 변경·정렬·숨김·복구 | 고정 ID와 연결 유지, 숨김은 공개 필터에서 제외, 복구하면 다시 표시 |
| 상품 분류 | 상품 등록과 운영 화면에서 상품당 한 개 지정·변경·해제 | 기존 상품은 미분류, 숨긴 분류로 새 지정 금지, 분류 변경 후 가격·재고·주문 보존 |
| 권한·호환성 | 공개 조회와 운영자 변경 분리, 기존 세션·권한·CSRF 적용 | 일반 회원·비회원 직접 변경 차단, 기존 상품 API·구매 흐름 유지, 내부 재고 수량 비노출 |

## 화면과 탐색 흐름

- 헤더 검색과 홈 카테고리 카드에서 `products.html`로 이동한다. 목록 화면은 검색 폼, 공개 카테고리 필터, 결과 수와 페이지 이동을 제공한다. 기존 카드와 상세 진입점을 재사용한다. `New In`은 별도 카테고리 없이 최신순 전체 목록으로 연결한다.
- 검색 제출 또는 필터 변경 시 페이지를 1로 바꾼다. 페이지 이동은 현재 조건을 유지한다. 일반 이동은 브라우저 기록을 남기고 뒤로·앞으로 가기는 URL 상태만 복원해서 조회한다. 재시도는 같은 URL 조건으로 조회한다.
- 로딩, 결과 없음, 네트워크·서버 실패, 숨김·존재하지 않는 분류를 별도로 표시한다. 실패를 0건으로 표시하지 않는다. 존재하지 않는 페이지는 빈 목록 및 첫 페이지 이동을 제공한다. 숨긴 분류의 공유 링크는 필터 이용 불가를 안내하고 전체 목록으로 돌아가는 동작을 제공한다.
- 요청 순서가 뒤집히면 최신 탐색에 해당하는 응답만 반영한다. 검색어·카테고리 이름은 텍스트로 렌더링한다. 로딩·오류는 스크린리더에 알리고 모바일과 데스크톱에서 키보드로 조작할 수 있게 한다.
- 운영 화면은 카테고리 목록(숨김 포함), 추가·이름 수정·정렬·숨김·복구, 상품의 현재 분류와 지정·해제를 제공한다. 권한 만료나 오류 시 성공을 표시하지 않고 재로그인 또는 명시적 재시도를 안내한다. 복귀 시 쓰기를 자동 반복하지 않는다.

## API 계약

기존 `/api/products`와 `/api/products/{productId}`의 응답을 유지한다. 운영자 전용 재고 응답에 현재 분류의 `categoryId`를 추가한다. 운영 API는 기존 운영자 판정과 JSON·CSRF 정책을 적용하고 기존 공통 응답과 오류 형식을 사용한다.

| API | 입력·동작 및 결과 |
| --- | --- |
| `GET /api/products/search?q=&category=&page=` | 공개 조회. `q`는 양끝 공백 제거 후 최대 100자이며 빈 값은 전체 이름에 해당한다. 영어는 대소문자를 무시하고 `%`, `_` 같은 문자는 검색 패턴으로 해석하지 않는다. `category`는 선택적 양의 카테고리 ID, `page`는 1부터 시작하는 정수(기본 1). 고정 24개, 등록일 내림차순과 ID 내림차순으로 정렬. `data`에 `items`, `totalItems`, `page`, `totalPages`를 포함한다. 입력 오류는 400, 숨김·미존재 분류는 같은 404, 결과 없는 페이지는 200과 빈 `items`를 반환한다. |
| `GET /api/products/categories` | 공개 카테고리의 `id`, `name`, `sortOrder`를 운영자 지정 순서와 ID 순으로 반환. |
| `GET /api/products/admin/categories` | 운영자 전용. 숨김을 포함한 분류와 `visible` 상태 조회. |
| `POST /api/products/admin/categories` | 운영자 전용. `name`으로 분류를 추가하고 기본 공개 상태로 맨 뒤에 배치. |
| `PATCH /api/products/admin/categories/{id}` | 운영자 전용. `name`, `sortOrder`, `visible` 중 전달된 값으로 부분 갱신. 없는 ID는 404, 중복 이름은 409. |
| `PUT /api/products/admin/{productId}/category` | 운영자 전용. `categoryId`로 분류 지정 또는 `null`로 해제. 없는 상품·숨김·미존재 분류에는 새로 연결할 수 없다. 카테고리 숨김과 지정이 경합해도 숨긴 뒤 새 지정은 성공하지 않는다. |

기존 상품 등록의 JSON·멀티파트 DTO는 `categoryId`를 선택 입력으로 받는다. 생략하면 미분류로 등록한다. 분류의 표시 이름은 1~80자이고 앞뒤 공백을 제거한다. 대소문자만 다른 이름은 중복으로 취급하고 DB에서 동시 중복도 막는다. 정렬값은 0~2,147,483,647의 정수이고 동률이면 ID 순으로 고정한다. 유효하지 않은 요청은 상태를 바꾸지 않는다.

## 저장·이행과 호환성

- Flyway V14에 카테고리 테이블과 상품의 nullable 카테고리 FK를 추가한다. 기존 상품을 자동 분류하지 않는다. 초기 카테고리 `Mugs`, `Tableware`, `One Piece`에 고정 ID와 초기 표시 순서를 부여해 홈 링크를 연결한다.
- 카테고리 숨김은 정렬과 상품 연결을 보존한다. 숨긴 카테고리에 속한 상품은 직접 필터에서 제외되며 전체 목록·이름 검색·상품 상세에서는 기존 판매 상태 그대로 조회된다. 공개 응답에는 내부 재고·예약·버전 값을 추가하지 않는다.
- 서버에서 필터·정렬·페이지 크기를 강제한다. 검색 조건은 파라미터로 바인딩한다. FK와 카테고리 정렬 및 상품 페이지 조회에 필요한 인덱스를 이행에서 검토한다. 마이그레이션은 기존 상품·판매 상태·가격·재고·주문을 보존하고 V1~V13 체크섬을 유지한다.
