## 목표와 범위

현재 홈·상품 목록·상세·장바구니 등에 흩어진 FAQ와 1:1 Q&A 링크를 실제 고객센터로 연결한다. FAQ는 공개하고, 문의 내용과 답변은 문의한 회원과 운영자만 볼 수 있다. 첨부파일, 답변 후 추가 대화, FAQ 편집 화면과 외부 발송은 후속 범위다. 문의를 접수하거나 답해도 주문·배송·환불 상태는 변경되지 않는다.

| 작업 항목 | 구현 범위 | 인수 기준 |
| --- | --- | --- |
| 공개 FAQ | 검토된 문답의 저장소 파일, 배포 시 반영, 승인 정책으로 연결 | 로그인 없이 조회 가능. 승인되지 않은 배송비·기한·환불 조건을 표시하지 않음 |
| 회원 문의 접수 | 제목·본문, 선택적으로 본인 주문 한 건, 요청 키 | 주문 없이 접수 가능. 타인·미존재 주문 동일 오류, 재시도 때 중복 접수 방지 |
| 내 문의·답변 조회 | 본인 목록·상세, 접수 시각과 답변 대기·완료, 확정 답변 | 타인·미존재 문의 동일 404, 로그인 복귀는 조회만 수행 |
| 운영자 답변 | 상태별 문의 목록·상세, 텍스트 답변 1건 | 답변과 완료 상태 동시 확정, 경합 시 1건만 기록, 일반 회원의 직접 호출 차단 |

## 화면과 운영

- 고객센터에는 FAQ와 1:1 문의 진입점을 둔다. FAQ는 계정·주문 조회 등 현재 기능의 이용법을 안내한다. 배송비·반품 기간 등 운영 값은 FAQ에 복제하지 않고 승인된 정책 화면으로 연결한다. 공개 문서가 없으면 준비 상태를 안내하며, 합성 정책을 운영에 게시하지 않는다. FAQ 파일은 저장소에서 검토하고 배포 때만 반영한다. 목록은 누락·손상으로 조회할 수 없는 경우와 정상적인 빈 목록을 구분한다.
- 문의 화면은 로그인 후 본인 문의 목록과 상세를 보여준다. 문의 폼은 주문 없이도 열 수 있으며, 본인 주문 선택 목록에는 기존 주문 조회를 재사용한다. 접수 후 문의 상세에서 접수 여부를 확인한다. 검증 실패에는 입력을 유지하고, 네트워크 오류 시 성공을 단정하지 않는다. 로그인 복귀에서 안전한 고객센터 또는 문의 화면만 열고 쓰기를 다시 실행하지 않는다.
- 운영 화면은 답변 대기와 완료를 필터로 제공한다. 답변 확정 후 회원 상세에서 즉시 조회할 수 있다. 이미 완료된 문의에 추가 전송하면 기존 답변을 보존하고 새로고침을 안내한다. 운영자 서명 정보·내부 회원 ID·주문 배송지와 결제 상세는 회원 화면에 포함하지 않는다.
- 제목·본문·답변은 텍스트로 렌더링하고 HTML·첨부파일을 받지 않는다. 폼에는 비밀번호·결제 정보 등 불필요한 민감정보를 적지 않도록 안내한다. 접근 거부·조회 실패·빈 목록·저장 성공은 명확히 구분하고 상태 안내와 조작은 키보드로 이용 가능하게 한다.

## API·데이터 계약

기존 Controller → Service → Repository 구조, 공통 응답·오류, 세션 및 CSRF 규칙을 재사용한다. 회원·운영자 문의 API는 캐시하지 않는다. 상태 변경은 인증된 세션의 POST에서만 수행하며 작성자 ID를 클라이언트에서 받지 않는다. 브라우저 쓰기는 현재 세션의 `X-Checkout-Account`를 전달하고 세션 계정과 다르면 409로 거부한다.

| API | 계약 |
| --- | --- |
| `GET /api/support/faq` | 공개 FAQ의 안정적인 항목 ID, 질문, 답변 텍스트, 필요한 정책 링크를 검토된 파일 순서대로 반환. 정상적으로 문답이 없으면 빈 목록, 카탈로그 로딩 불가 시 공통 오류. |
| `POST /api/support/inquiries` | 회원 전용. `title`, `body`, 선택 `orderId`와 `Idempotency-Key` 헤더를 받는다. 입력 오류 400, 타인·미존재 주문은 동일 404. 최초 저장 201, 동일 요청 재전송은 200으로 같은 문의 반환. 같은 키의 다른 내용은 409. |
| `GET /api/support/inquiries`, `GET /api/support/inquiries/{id}` | 로그인 회원의 문의만 조회. 목록은 기본 페이지 0, 20건, 접수 시각·ID 내림차순과 다음 페이지 여부. 상세에 문의 본문과 확정 답변을 포함. 타인·미존재 문의는 동일 404. |
| `GET /api/admin/support/inquiries`, `GET /api/admin/support/inquiries/{id}` | 운영자 전용. 목록은 회원 목록과 같은 페이지 규칙을 쓰며 선택 상태 필터 지원. 목록은 제목·시각·상태 중심, 상세에서 본문·답변·연결 주문번호 확인. |
| `POST /api/admin/support/inquiries/{id}/reply` | 운영자 전용. `body`를 받아 답변 1건을 확정한다. 미존재 404, 기존 답변이 있으면 409. 저장 실패 시 문의는 답변 대기에 남는다. |

- 제목은 양끝 공백 제거 후 1~100자, 문의와 답변 본문은 1~2,000자다. 본문의 내부 줄바꿈은 보존한다. 빈 값과 범위 초과는 서버에서 거부한다.
- 문의의 상태는 `PENDING`(답변 대기), `ANSWERED`(답변 완료)다. 답변 작성자 식별자와 답변 시각은 운영 감사에 필요한 범위에서 저장한다. 완료 답변 수정·삭제는 첫 버전에서 제공하지 않는다.
- Flyway V15에 문의 저장을 추가했다. 문의는 회원을 참조하고, 선택 주문은 서버가 `orderId`와 회원 ID로 소유권을 확인한 뒤 기존 주문 레코드를 참조한다. 회원과 요청 키에 유일 제약을 두고 정규화한 제목·본문·주문을 비교한다. 재시도 키는 동일 제출에 재사용하고 내용 변경 시 새 키를 쓴다. 답변과 상태 변경은 한 트랜잭션으로 확정한다.
- 로그와 검증 자료에는 문의 원문·연락처·배송지·세션·결제 키를 담지 않는다. 실데이터 보존 정책과 운영 담당자 지정은 출시 전 별도 확인한다.

## 인수 기준과 증거

| ID | 검증 | 기대 증거 |
| --- | --- | --- |
| SUPPORT-01 | 공개 FAQ, 정책 승인·미승인, 빈 목록·실패, 고객센터 링크 | HTTP 응답과 실제 브라우저에서 승인된 정책 링크·명확한 상태 확인 |
| SUPPORT-02 | 주문 없는 문의, 본인 주문 연결, 타인·미존재 주문, 입력 경계 | 저장·응답 대조, 잘못된 입력에 레코드 또는 주문 변경 없음 |
| SUPPORT-03 | 동일 키 재전송·동시 접수, 다른 내용 재사용, 응답 유실 | H2·MySQL에서 중복 1건 보장, 다른 내용 409, 명시적 재시도 |
| SUPPORT-04 | 목록 페이지, 타인 문의, 세션 만료·CSRF, 로그인 복귀 | 본인 데이터만 노출, 직접 요청 차단, 복귀 후 조회만 수행 |
| SUPPORT-05 | 운영자 상태별 목록과 답변, 동시 처리·DB 실패, 회원 답변 조회 | 최초 확정 답변 1건, 실패 시 상태 보존, 회원과 운영자 결과 일치 |
| SUPPORT-06 | 이행과 기존 주문·배송·환불 회귀, 문의 화면 접근성 | 이전 데이터 보존, 기존 API·구매 흐름 회귀 없음, 화면·HTTP·DB 증거 |

### 로컬 검증 결과

| ID | 상태 | 증거 |
| --- | --- | --- |
| SUPPORT-01 | PASS | 익명 HTTP와 Chrome에서 FAQ·정책 길을 확인했다. 카탈로그 단위 검증에서 정상 빈 목록과 잘못된 파일을 구분했다. 정책 게시 상태 검증은 기존 POLICY 회귀가 다룬다. |
| SUPPORT-02 | PASS | H2·MySQL·실제 HTTP에서 주문 없는 접수, 본인 주문 선택, 타인·미존재 주문 404, 입력 검증 및 기존 주문 상태 보존을 확인했다. |
| SUPPORT-03 | PASS | H2·MySQL에서 같은 키의 동시 접수는 한 건, 다른 내용 재사용은 충돌이다. 실제 HTTP로 재전송 응답을, JS로 응답 유실 후 키 재사용을 확인했다. |
| SUPPORT-04 | PASS | H2·MySQL에서 페이지와 본인만 조회, 타인·미존재 동일 오류, CSRF·만료·계정 불일치 차단을 검증했다. Chrome 로그인 복귀와 JS 뒤로 가기 복원에는 쓰기 재실행이 없었다. |
| SUPPORT-05 | PASS | H2·MySQL에서 상태 필터, 동시 답변 한 건, 롤백 후 답변 대기 보존을 확인했다. 실제 HTTP와 Chrome에서 운영자 답변 뒤 회원 상세에 확정 답변이 표시됐다. |
| SUPPORT-06 | PASS | V14→V15 보존 검증을 H2·격리 MySQL 8.4.13에서 실행했다. 모의 PG 실제 HTTP 6개 시나리오로 기존 주문·배송·취소·반품·환불·재입고를 확인했다. Chrome 접근성 트리에서 폼 라벨과 상태 안내를 확인했다. |

합성 회원·주문, 모의 PG와 이미지 저장소를 사용했다. 실제 정책 승인·FAQ 최종 검토·운영 활성화는 별도다.
