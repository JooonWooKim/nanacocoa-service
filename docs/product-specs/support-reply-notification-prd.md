## 목표와 인수 기준

운영자가 답변을 확정하면 문의한 회원이 사이트 알림함에서 새 답변을 확인하고 해당 문의 상세로 이동할 수 있다. 주문 연결은 선택 사항이다. 현재 문의당 답변 1건 정책을 유지한다. 이메일·SMS·푸시, 추가 대화와 답변 편집은 후속 범위다.

| 작업 항목 | 구현 범위 | 인수 기준 |
| --- | --- | --- |
| 답변 확정 감지 | 운영자 답변을 저장하는 트랜잭션에 UTC 확정 시각 기록. 기존 게시 작업이 커밋된 답변을 발견 | 답변 롤백·동시 제출·재시도에도 문의당 알림 최대 한 건. 기존 답변 이력은 소급 게시하지 않음 |
| 회원 알림함 | `SUPPORT_ANSWERED` 유형을 기존 목록·읽음·미읽음 수에 통합. 주문 연결 없는 문의도 지원 | 알림에 일반 안내와 문의 식별자만 표시. 답변 원문과 문의 제목은 본인 문의 상세에서만 조회 |
| 문의 상세 이동 | 알림에서 문의 상세 링크를 열고 기존 본인 상세 API로 조회 | 타인·미존재 문의는 동일한 404. 로그인 복귀는 조회만 수행. 계정 전환 후 이전 응답이 화면을 복원하지 않음 |
| 운영과 재처리 | 기존 실패 목록·누적 횟수·개별 재시도 재사용. 기본 비활성 및 별도 UTC 시작 시각 적용 | 게시 실패가 답변 저장에 영향을 주지 않음. 자동 재시도와 운영자 재처리 후에도 한 건만 게시 |

## 확정 처리와 이행

- 기존 운영자 답변 API와 완료 시 409 계약을 유지한다. 최초 `ANSWERED` 전이와 같은 트랜잭션에 알림용 서버 시각을 남긴다. 답변 응답은 기존 문의 저장 결과로 결정한다.
- V17은 `support_inquiries`에 조회용 인덱스를 갖는 nullable UTC 확정 시각을 추가한다. 기존 답변의 시각은 비워 둔다. `order_notifications`에 nullable 문의 참조와 문의당 한 건의 유일 제약을 추가한다. 주문 참조의 기존 유일 제약을 유지하고, 주문 유형은 주문 ID와 주문번호를, 문의 유형은 문의 ID만 갖도록 DB에서 검증한다. 알림 소유자는 원본 문의 회원으로 기록한다. V15·V16 이력, 기존 알림 ID·읽음 시각·실패 상태는 보존한다.
- 기존 작업이 활성일 때 `notifications.support.enabled`를 추가로 활성화해야 문의 알림을 게시한다. 기본값은 false다. 활성화 시 `notifications.support.starts-at`에 UTC 시작 시각을 요구하며, 기준 시각을 포함한다. 문의 작업의 탐색과 대기 재처리에 같은 조건을 적용한다. 기존 주문 알림 유형은 기존 기준 시각을 계속 사용한다.
- 기존 30초 주기, 제한된 배치, 행 잠금과 실패 기록을 사용한다. 문의당 한 건으로 탐색·게시 경합을 처리한다. 게시 실패는 별도 트랜잭션에서 최대 3회 시도하고, 운영자 재시도는 새 시도 주기를 시작하며 총 시도 횟수를 보존한다. 같은 시작 시각으로 재개하면 저장된 미처리 확정 건을 다시 읽는다.

## 화면·API와 개인정보

| 기존 인터페이스 | 후속 변경 |
| --- | --- |
| `GET /api/notifications`, `PUT /api/notifications/{id}/read` | 문의 알림 항목에만 `inquiryId`를 십진 문자열로 반환한다. 기존 주문 항목 형식은 유지한다. 두 유형을 확정 시각·ID 내림차순으로 페이지 처리하고 전체 미읽음 수를 제공한다. |
| `GET /api/admin/notifications`, `POST /api/admin/notifications/{id}/retry` | 기존 운영자 API에 문의 유형과 문의 식별자를 포함한다. 실패한 알림만 대기로 전환하고 기존 성공·대기 알림을 중복 처리하지 않는다. |
| `GET /api/support/inquiries/{id}` | 응답과 본인 인가 계약을 유지한다. 알림 링크 `support-inquiries.html?inquiryId=…`에서 유효한 양의 정수 ID를 검증하고 이 API로 상세를 연다. |

알림은 ‘문의에 답변이 등록되었습니다’를 표시한다. 링크 이동은 읽음이나 답변 변경을 자동 요청하지 않는다. 로그인 복귀에는 허용된 문의 경로와 검증된 문의 ID만 전달한다. 세션 만료·계정 전환·페이지 이탈 시 이전 화면을 지우고 지연 응답을 무효화한다. 기존 세션·CSRF·캐시 금지·운영자 인가 규칙을 적용한다. 제목·본문·답변·운영자 정보·세션 값은 알림 응답과 운영 로그에 담지 않는다.
