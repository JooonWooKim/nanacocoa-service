## 사용자 흐름

담당자가 기존 장애 해결 자료의 비식별 이벤트 파일과 요청 번호 또는 자동 복구 실행 번호를 지정한다. CLI가 근거를 검증하고 모의 모델로 원인 후보와 다음 확인 절차를 제안한다. 담당자는 근거가 연결된 원인 후보와 기존 권장 검사를 읽고 적용할 확인 절차를 판단한다.

첫 버전은 로컬 CLI에서 모의 모델로 검증한다. 실제 모델 호출, Slack 회신 변경, 패치 생성·적용, 테스트 자동 실행, 운영 로그 연결과 배포는 후속 범위다.

## 작업과 인수 기준

| 작업 항목 | 구현 범위 | 인수 기준 |
| --- | --- | --- |
| 분석 입력 | `incident-analyze`의 입력 파일과 요청·실행 번호를 기존 `incident-evidence` 계약으로 검증 | 후보 커밋과 현재 체크아웃이 일치해야 한다. 선택한 번호의 이벤트만 모델에 전달하고 증거 부족은 모의 모델 호출 전에 보류한다. |
| 원인 후보와 근거 | 모의 모델이 원인 후보, 근거 참조와 다음 확인 절차를 반환 | 선택한 번호의 이벤트와 같은 커밋의 허용된 코드·운영 문서로 참조를 제한한다. 검증할 수 없는 참조는 채택하지 않는다. |
| 검증 안내 | 기존 해결 자료의 권장 검사를 분석 결과와 함께 출력 | 재고 예약 실패는 잠금·롤백, 결제 승인 미확정은 저장된 거래 상태 조회를 먼저 안내한다. 담당자가 확인 절차와 실제 검사 실행을 결정한다. |
| 한도와 실패 처리 | 한 실행에 모델 호출 최대 1회, 입력 16 KiB, 출력 4 KiB와 처리 시간 5초 | 유효한 분석은 PASS, 증거 부족·한도 초과는 BLOCKED, 계약 오류는 FAIL이다. 호출 횟수와 처리 시간을 남기고 실제 모델 비용은 0이다. |

## 실행·데이터 계약

하네스에 `incident-analyze` 하위 명령을 추가한다. 요청 분석은 `--input <파일> --request-id <UUID>`, 자동 복구 분석은 `--input <파일> --run-id <UUID>`를 사용한다.

- `--input`은 기존 `incident-evidence`와 같은 비식별 이벤트 JSON 파일이다. `candidateCommit`과 `events`를 검증하고 UUIDv4 하나를 선택한다. 기존 하네스가 검증한 구조화 이벤트, 허용된 근거 식별자와 권장 테스트만 분석 입력으로 구성한다. 출처 경로는 기존 해결 자료가 제시하고 후보 커밋에서 확인한 고정 코드·문서 경로를 사용한다.
- 입력 파일과 모의 모델 입력은 각각 UTF-8 16 KiB, 모의 모델 출력은 UTF-8 4 KiB로 제한한다. 파일 확인부터 분석 결과 생성까지 5초를 제한 시간으로 적용하고, 남은 시간 안에서 하위 작업을 종료할 수 있어야 한다. 지원하는 세 장애 유형에 해당하지 않으면 모의 모델 호출 전에 BLOCKED를 반환한다. 한 실행에서는 모델을 자동 재호출하지 않는다.
- 모의 모델 결과는 원인 후보·근거 참조·다음 확인 항목을 포함하는 구조화 값으로 받는다. 도구와 임의 경로를 전달할 수 있는 필드는 허용하지 않는다. 근거 참조는 선택된 타임라인 항목과 기존 해결 자료의 출처 목록에 대조한다. 원인 후보는 근거와 함께 표시하며 담당자가 원인을 확정한다.
- 표준 출력에 판정·고정 사유, 확인한 후보 커밋, 원인 후보와 근거, 후속 확인 절차, 기존 권장 테스트, 호출 횟수·처리 시간·실제 모델 비용을 JSON으로 기록한다. 종료 코드는 기존 하네스 예에 맞춰 PASS 0, FAIL 1, BLOCKED 2를 사용한다. 계약 실패와 보류 결과에는 검증된 식별자와 고정 안내만 포함한다.
- 원본 로그·요청 본문·고객 정보·비밀값·임의 명령은 입력과 결과의 허용 목록에서 제외한다. 담당자는 분석 결과와 실제 테스트 결과를 각각 확인한다. 모의 모델과 CLI는 외부 네트워크나 저장소 쓰기 권한을 사용하지 않는다.

## 인수 검증

| 시나리오 | 확인할 결과 |
| --- | --- |
| 재고 예약 실패 | 같은 주문 흐름의 예약·잠금 및 롤백 확인 절차와 기존 권장 테스트가 제공된다. |
| 결제 승인 미확정 | 결과를 미확정으로 유지하며 저장된 거래 조회를 우선 안내한다. |
| 자동 복구 실패 | 지정한 실행 번호의 실패 작업과 같은 실행의 근거만 인용한다. |
| 입력·근거 경계 | 다른 번호 제외, 커밋 불일치·증거 부족의 호출 전 보류, 허용되지 않은 입력·근거 참조의 거부를 검증한다. |
| 한도·회귀 | 입력·출력 크기 초과, 처리 제한 초과, 잘못된 모델 출력, 한 실행당 호출 횟수를 검증한다. 기존 해결 자료와 모의 Slack 접수·회신 회귀 및 전체 하네스를 실행한다. |

## 로컬 구현

`incident-analyze`는 기존 증거 검증을 사용하고 모의 모델 결과의 인용 이벤트와
출처를 해당 장애 유형에 대조한다. 유효한 결과에는 `hypotheses`와 `recommendedTests`가
포함된다. `modelCalls`, `durationMs`, `modelCost`는 보류·실패에도 제공된다.
집중 검사 9개에서 세 장애 유형, 경계 위반, 한도와 제한 시간을 검증했다.
전체 Python 44개와 H2 Java 268개가 통과했다. 전체 하네스는 기존
아키텍처·보안 예외가 유지된 `BASELINED`다. 실제 모델과 운영 연결은 후속 인수다.
