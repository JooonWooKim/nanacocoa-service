# 핵심 엔지니어링 원칙

상태: 검증됨
갱신 조건: 반복된 리뷰에서 원칙이 잘못되었거나 불완전하다고 확인될 때

1. **저장소가 기록이다.** 아키텍처, 명령, 위험, 결정, 운영 지식은 이
   저장소에서 검색 가능하고 버전 관리되어야 합니다.
2. **지도는 매뉴얼보다 낫다.** `AGENTS.md`는 모든 규칙을 매 작업에 넣는
   대신 작고 권위 있는 문서로 에이전트를 안내합니다.
3. **핵심 경계는 실행 가능해야 한다.** 아키텍처, 마이그레이션 무결성,
   비밀값 안전, 평가 기대값에는 기계적 검사가 필요합니다.
4. **실패는 인터페이스다.** 유용한 실패는 무엇이 깨졌고, 왜 중요하며,
   어디를 보고, 다음에 무엇을 실행할지 알려줍니다.
5. **기준선을 잡고 래칫을 건다.** 기존 결함은 계속 드러나며 증가할 수
   없습니다. 기준선 예외는 성공이 아니라 부채입니다.
6. **단순하고 검사 가능한 것이 이긴다.** 불투명한 자동화보다 저장소 소유
   스크립트, Gradle, 타입 경계, 결정적 산출물을 선호합니다.
7. **중앙 제약과 지역적 자유.** 의존 방향, 안전, 정확성은 강제하되 그
   범위 안에서는 구현 선택을 허용합니다.
8. **외부 효과에는 더 강한 권한이 필요하다.** 로컬 검사와 테스트는
   자율적으로 수행합니다. 배포, 실제 제공자 호출, 데이터 삭제, push,
   merge에는 명시적 승인이 필요합니다.
9. **증거가 작업을 닫는다.** 테스트 보고서, 생성 산출물, 명령 상태, 리뷰
   결과를 완료 주장과 함께 남깁니다.
10. **엔트로피는 지속적이다.** 작고 반복적인 진단과 표적 정리가 간헐적인
    대규모 재작성보다 저렴합니다.
