# 실행 계획

상태: 활성

여러 단계로 진행되거나, 위험하거나, 여러 도메인에 걸치거나, 아키텍처·
데이터를 변경하거나, 하나의 Codex context보다 오래 지속될 수 있는 작업은
저장소 실행 계획을 사용합니다.

1. [PLANS.md](PLANS.md)를 `active/<설명적인-이름>.md`로 복사합니다.
2. 모든 필수 섹션을 저장소 증거로 작성합니다.
3. 작업 중 진행 상황, 결정, 명령, 위험을 갱신합니다.
4. 검증 결과를 PASS, FAIL, BLOCKED, SKIPPED, BASELINED로 분류합니다.
5. 결과와 남은 부채가 명확해진 후에만 파일을 `completed/`로 이동합니다.

계획은 약속이 아니라 결정과 증거의 기록입니다. 구현이 계획과 달라지면
그 이유를 기록합니다.
