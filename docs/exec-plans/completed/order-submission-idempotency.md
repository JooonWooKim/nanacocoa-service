# 주문 제출 멱등성

상태: 완료

## 목표

회원의 동일 checkout 제출에서 주문과 최초 재고 예약을 최대 한 번 생성한다.
[구현 PRD](../../product-specs/order-submission-idempotency-prd.md)의 계약을 따른다.

## 하지 않는 일

운영자의 미확정 거래 조회, 취소·반품·환불, 장바구니, 운영 PG 활성화는 후속 범위다.

## 현재 증거

- 원격 `main` 기준: `b9ee6198f963ce56118d2dfcbd7b841ec6e34640`.
- 결제 환경 분리 [PR #17](https://github.com/JooonWooKim/nanacocoa-service/pull/17)이
  병합됐다. 배송·반품 정책이나 약관 승인 없이 주문 제출을 독립적으로 개선할 수 있다.
- `OrderService.createOrder`는 요청마다 새 주문 번호를 만들고 재고를 예약한다.
  checkout의 기존 결제 승인 키는 주문 생성에 사용되지 않는다.

## 결정

서버는 주문 생성에서 회원 행을 먼저 잠그고 제출 키를 확인한다. 새 주문만
상품 행을 ID 오름차순으로 잠그며 주문·키·최초 예약을 함께 커밋한다.
checkout은 응답을 받지 못하면 본인 제출 결과를 조회하고, 결제창을 열기 전에
현재 계정과 예약 상태를 다시 확인한다.

## 위험과 롤백

같은 키에서 동시 제출, 마지막 재고 경쟁, 커밋 뒤 응답 유실을 검증한다.
배포한 Flyway 버전은 수정하지 않는다. 이행 후 앱을 되돌리는 경우 이전 앱은
제출 키를 강제하지 않으므로 checkout 중복 보호가 보장되는 배포 조합을 확인한다.

## 미해결 항목

운영 반영 시 API와 checkout 정적 파일을 함께 배포한다. 임시 DB와 모의
결제 브라우저 결과는 운영 결제·배포 환경의 검증과 별개다.
