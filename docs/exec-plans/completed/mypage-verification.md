# 마이페이지 진입 본인 확인

상태: 완료

## 목표

현재 비밀번호를 확인한 로그인 세션만 회원정보 화면과 API에 접근합니다.

## 하지 않는 일

기존 사용자 수정, 전역 CSRF 정책 변경, 배포, DB 마이그레이션은 하지 않습니다.

## 현재 증거

마이페이지와 회원 조회는 로그인만 요구했습니다. 기존 CSS/HTML 수정은 보존합니다.
전체 검사는 생성 문서 불일치가 있고 엄격 테스트에는 알려진 실패 5개가 있습니다.

## 결정

- 별도 확인 페이지와 JSON POST 확인 API를 만듭니다.
- 확인은 10분 동안 세션·사용자·현재 비밀번호 hash에 결합합니다.
- 비밀번호 확인 5회 실패 후 해당 세션의 5분 시도 구간이 끝날 때까지 차단합니다.
- 로그인·로그아웃·비밀번호 변경 시 확인 상태를 무효화합니다.
- 새 확인 API는 커스텀 헤더를 요구하고 CORS 권한을 부여하지 않습니다.
- 저장 시 현재 비밀번호 재검증은 유지합니다.

## 위험과 롤백

세션 확인 상태가 없거나 만료되면 접근을 거부합니다. 비밀번호는 브라우저 저장소나
URL에 저장하지 않습니다. 이 변경만 되돌릴 수 있으며 DB 변경은 없습니다.

## 미해결 항목

이번 변경의 미해결 항목은 없습니다. 기존 전역 CSRF 비활성화·로그아웃 GET·
세션 ID 미회전은 NC-SEC-001~003으로 남아 있습니다. 새 확인 API의 커스텀
헤더와 CORS 거부가 기존 인증 전체의 보안 부채를 해결한다는 의미는 아닙니다.
반복 실패 제한은 로그인 세션 단위이며 계정/IP 단위 분산 제한은 이번 범위 밖입니다.
실행 중인 기존 서버의 smoke는 상태 검사이며, 새 기능의 서버 검증은 H2 통합
테스트로 수행했습니다. 실행 서버 재빌드·재시작은 수행하지 않았습니다.

## 최종 리뷰

- API는 현재 로그인 이메일로만 조회하며 확인 상태를 사용자·세션·credential에 결합합니다.
- 미확인·만료·변경된 credential은 접근 거부, 저장은 기존 현재 비밀번호 검증을 유지합니다.
- 비밀번호는 URL·브라우저 저장소·응답에 포함하지 않고 확인 폼은 요청 종료 시 비웁니다.
- 기존 UI 정렬을 보존했고 DB·마이그레이션·외부 결제·S3·실제 회원 데이터는 변경하지 않았습니다.
