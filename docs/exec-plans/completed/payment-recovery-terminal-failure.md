# 결제 복구에서 최종 실패 시 예약 재고 해제

상태: 완료

## 목표

결제 복구에서 확정 실패를 확인하면 주문의 예약 재고를 한 번만 해제합니다.

## 하지 않는 일

승인 요청의 오류 분류, 상품 화면, Flyway 이력 변경은 범위 밖입니다.

## 현재 증거

`ABORTED`와 `EXPIRED`가 보상 대기로 남으면 주문에 확보된 재고가 계속 예약됩니다.

## 결정

- `ABORTED`와 `EXPIRED`가 보상 대기로 남던 경로에서 기존 `failApproval`로 결제·주문·재고를 함께 전이합니다.
- 결제 키·주문 번호·금액 중 하나라도 다르면 기존 복구 동작을 다시 예약합니다.
- 테스트에서 토스 조회 응답을 모의합니다. 기존 Flyway 이력을 유지합니다.

## 진행 상황

- 2026-11-14: 결제 복구 분기를 수정하고 회귀 테스트와 운영 절차를 갱신했습니다. 집중 테스트가 통과했습니다. 최초 전체 하네스에서 문서 양식 검사가 실패해 실행 계획을 템플릿에 맞췄습니다.

## 명령과 증거

| 명령 | 상태 | 증거 |
| --- | --- | --- |
| `./gradlew test --tests '*PaymentRecoveryServiceTest' --tests '*InventoryIntegrationTest'` | PASS | H2와 모의 토스로 테스트 27개 통과 |
| `./scripts/harness test-baseline` | BASELINED | 전체 검사 중 실행. 120개, skip 0개, 기존 실패 fingerprint 5개 일치 |
| `./scripts/harness smoke` | SKIPPED | 전체 검사 중 Compose 구성 검증 통과. 실행 중인 Compose 앱 없음 |
| `./scripts/harness docs` | PASS | 실행 계획 양식 수정 후 통과 |
| `git diff --check` | PASS | 공백 오류 없음 |

최종 `./scripts/harness check` 결과는 [하네스 요약](../../../build/harness/check-summary.txt)에 기록합니다.

## 위험과 롤백

서로 다른 결제의 조회 응답으로 재고를 풀지 않도록 세 식별 값을 대조합니다. 상태 전이는 기존 주문 행 잠금과 재고 트랜잭션을 따릅니다. 되돌릴 때 이 변경에 포함된 소스·테스트·문서 차이만 되돌립니다.

## 미해결 항목

이번 수정의 집중 검증은 H2에서 진행했습니다. Compose 런타임 검증은 실행 스택이 있는 환경에서 가능합니다.
