# 이슈 #22 미확정 거래 운영 구현

상태: 완료

## 목표

관리자 미확정 거래 조회·상세·개별 복구를 PRD대로 구현한다.

## 하지 않는 일

신규 취소·반품, 스키마, 운영 설정, 커밋·push·PR은 변경하지 않는다.

## 현재 증거

기존 복구는 주문 락과 REQUIRES_NEW 상태 전이를 사용한다. 테스트 프로필의 LocalPaymentLock은 무잠금이므로 새 통합 테스트에 주문별 직렬화 어댑터를 사용한다. 기존 healthApiReturnsOk 실패는 NC-TEST-001이다.

## 결정

기존 테이블을 UNION ALL로 조회하고 DTO에는 허용 필드만 매핑한다. 수동·자동 복구가 락 안에서 재시도 시각을 재검증한다. Redis 서비스 장애는 기존 503을 유지한다. DB 스키마와 운영 설정은 바꾸지 않는다.

## 위험과 롤백

결제·취소·재고 중복 반영과 PG 응답 불일치를 집중 테스트한다. 테스트는 가상 데이터와 모의 PG만 사용한다. 코드·화면을 이전 버전으로 되돌릴 수 있으며 스키마 이행은 없다. 기존 사용자 문서는 보존한다.

## 미해결 항목

기능의 미해결 결정은 없다. 출시 전 운영 담당자와 문의 이관 기준 확정은 운영자 책임이다.

## 완료 조건

H2·임시 MySQL 집중 테스트, 브라우저, JavaScript 검증 및 전체 하네스 결과를 분류하고 문서와 실제 동작을 대조한다. 기존 실패 기준선을 약화하지 않는다.

- 2026-11-18: H2 집중 테스트와 임시 MySQL 8.4.10의 운영 통합 테스트 13개를 통과했다. Chrome에서 가상 운영자 로그인 복귀·검색·개별 복구 후 판매 확정·새로고침과 모바일 390px 무가로넘침을 확인했다. Node 검증은 응답 유실 후 GET만 실행, 중복 클릭 방지, CSRF 안내와 복귀 URL 제한을 통과했다.

- 2026-11-18: 전체 하네스는 BASELINED로 종료했다. 실패·마이그레이션 checksum 기준선은 변경하지 않았고, 전체 발견 테스트 목록에 검증된 테스트 13개만 추가했다. JavaScript 검증도 통과했다.
- 2026-11-18: 회귀·보안·데이터 손실 관점에서 DTO 허용 필드, DB 관리자 검증, CSRF, 재시도 시각 재검증, PG 응답 일치 검사와 기존 재고 경계를 리뷰했다. 운영 활성화·스키마 변경은 없고 커밋·push·PR은 수행하지 않았다. 검증용 서버와 이번 작업의 임시 MySQL 컨테이너는 중지했다. 기존 스택은 유지했다.
- 2026-11-18: 기존 문서 중 의도한 출시·기능 PRD 갱신 외 파일은 시작 시 SHA-256과 동일함을 확인했다. 화면 증거는 `build/harness/payment-operations-desktop.jpg`, 전체 하네스 요약은 `build/harness/check-summary.txt`다. 완료 기록 저장 후 문서·변경 형식을 다시 확인한다.
