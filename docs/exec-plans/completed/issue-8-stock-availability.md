# 이슈 #8 재고·품절 관리

상태: 완료

## 목표
동시 주문 초과 판매를 방지하고 재고 확보·결제·해제·검수 후 재입고와 품절 UI를 구현합니다.

## 하지 않는 일
실제 PG/S3 호출, 배포, 기존 데이터 삭제, 브랜치 전환·커밋·push는 하지 않습니다.

## 현재 증거
Products에 재고가 없고 OrderService는 재고 검증 없이 생성합니다. PaymentTransactionalService는 주문 잠금과 별도 트랜잭션을 사용합니다. 기존 테스트 실패 5개는 기준선입니다. 기존 미추적 점검 문서 2개를 보존합니다.

## 결정
- 재고는 주문 생성 시 상품 ID 오름차순 DB 쓰기 잠금으로 확보합니다. 상품별 판매 가능 수량과 예약 수량을 관리합니다.
- 15분 후 CREATED 주문만 만료합니다. PAYMENT_PENDING은 결과가 확정될 때까지 확보를 유지합니다. 승인 준비도 같은 주문 행 잠금을 사용하여 만료와 직렬화합니다.
- 확정 승인 실패/보상은 예약 재고를 해제합니다. 같은 주문 재시도는 재고를 다시 확보해야 합니다. 취소된 판매 재고는 검수 후 관리자 재입고를 통해서만 복원합니다.
- 기존 상품은 재고 0·판매 중지로 이행합니다. 기존 주문은 LEGACY로 표시하고 새 승인 진입을 막되 기존 진행 결제의 복구는 허용하며 재고를 자동 생성하지 않습니다.
- 재고 조정은 기대 버전을 검증하며 예약 수량은 변경하지 않습니다.

## 위험과 롤백
결제·재고 불일치가 주요 위험입니다. 동일 트랜잭션 상태 전이 및 집중 동시성 테스트로 검증합니다. 적용된 마이그레이션은 수정하지 않습니다. 배포 전 결제 진행 상태를 점검하고 구버전과 혼합 실행하지 않습니다.

## 미해결 항목
기능 구현 범위는 완료했습니다. 실제 제공자 결제는 호출하지 않았습니다. 배포 전 진행 결제 감사·DB 백업·기존 재고 실사와 등록은 운영자 작업으로 남습니다. 부분 반품/부분 재입고는 기존 전체 취소 모델의 범위 밖입니다. CI에서의 자동 MySQL 생명주기는 NC-DATA-002로 유지합니다.
