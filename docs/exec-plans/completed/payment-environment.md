# 결제 환경 분리와 모의 PG 검증

상태: 완료

## 목표

기본 실행과 테스트에서 실 PG를 호출하지 않고 명시적 운영 설정으로만 활성화한다.
checkout 결정과 승인·취소 API의 비활성 동작을 일치시킨다.

## 하지 않는 일

주문 제출 멱등성, 주문·결제·재고 상태 전이 변경, 운영 미확정 거래 화면, RETURN
연동과 브라우저 종단 검증은 후속으로 둔다.

## 현재 증거

- 세션 보안 PR #15가 병합된 원격 main에서 PAY 단계를 선정했다.
- 이슈 #16, 작업 브랜치 `branch/16`, [구현 PRD](../../product-specs/payment-environment-prd.md).
- 기존 PG 어댑터는 HTTP 클라이언트를 항상 생성했고 자동 복구도 기본 활성화였다.
- 기존 상태 확인 테스트 1건은 NC-TEST-001로 추적한다.

## 결정

실 PG는 활성 `prod` 프로필, 승인된 주소, 라이브 키 유형과 명시적 플래그를 요구한다.
브라우저 SDK는 결제 설정 성공 후 불러온다. 모의 PG는 테스트에서만 HTTP 어댑터
경계에 주입한다.

## 위험과 롤백

비활성화된 동안 미확정 거래는 자동 복구되지 않으므로 운영 절차에 따라 대조한
뒤 복구를 다시 연다. 스키마 변경이 없어 환경 플래그와 이 이슈 변경으로 되돌릴 수
있다. 키 원문을 출력하거나 기록하지 않는다.

## 미해결 항목

PAY 후속 작업과 운영 인수는 출시 PRD에서 추적한다. 상태 확인 실패는 NC-TEST-001로 유지한다.

## 완료 조건

결제 집중 테스트와 `./scripts/harness check`에 신규 실패가 없다. 결제로 인한
데이터 변경과 외부 호출이 비활성 상태에서 생기지 않음을 검토했고,
안전한 기본값과 운영 사용법을 문서에 반영했다.
