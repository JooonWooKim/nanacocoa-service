# Checkout 결제 설정 재확인

상태: 완료

## 목표

결제가 비활성화되면 Checkout의 주문 생성과 재고 예약 요청을 차단한다.

## 하지 않는 일

결제 API, 서버의 주문·결제·재고 상태 전이 및 스키마는 기존 계약을 따른다.

## 현재 증거

[결제 환경 PRD](../../product-specs/payment-environment-prd.md)의 비활성 안내 계약을
기준으로 실제 Checkout 핸들러를 모의 실행했다. 같은 탭의 재제출은 이전 설정을
재사용했고, 기존 주문 재시도는 비활성 응답을 받기 전에 재고 예약을 요청했다.

## 결정

시도마다 브라우저 캐시를 우회해 서버 설정을 조회한다. 설정 확인에 성공한 뒤
신규 주문은 SDK를 준비하고, 기존 주문은 재고 예약 성공 후 SDK를 준비한다.

## 작업 분해

- [x] 신규 주문 재제출과 기존 주문 재시도의 요청 순서 확인
- [x] Checkout에서 설정 조회와 SDK 초기화 분리
- [x] 모의 Checkout, 결제·재고 집중 테스트, 로컬 CI 검증

## 진행 상황

- 2026-11-17: 모의 HTTP 응답으로 이전 설정 재사용과 비활성 상태의 예약 요청을 재현했다.
- 2026-11-17: 결제 설정을 시도마다 조회하도록 변경하고 신규 주문·기존 주문의 정상 및 오류 경로를 점검했다.
- 2026-11-17: 정적 리소스 테스트가 제거된 함수 이름을 검사하는 것을 확인하고, 결제 설정 조회부터 멱등성 키 갱신까지의 새 순서를 검사하도록 갱신했다.
- 2026-11-17: 전체 하네스 재실행에서 신규 실패가 없음을 확인했다.

## 명령과 증거

| 명령 | 상태 | 증거 |
| --- | --- | --- |
| `node` (모의 Checkout) | FAIL | 수정 전 두 경로에서 결제가 비활성화된 뒤 주문 또는 예약 API를 호출했다. |
| `node --check src/main/resources/static/script.js` | PASS | Checkout 스크립트 문법을 검증했다. |
| `node` (모의 Checkout) | PASS | 같은 탭의 설정 변경, 정상 주문, 비활성 재시도, 동일 주문 재시도와 예약 충돌 등 5개 시나리오를 통과했다. |
| `./gradlew test` (결제·재고 집중 필터) | PASS | 비활성 결제 API를 포함한 65개 테스트를 통과했다. |
| `./scripts/harness check` (첫 실행) | FAIL | `servesStaticPages`가 제거된 함수 이름을 검사했다. 검증 순서를 새 흐름에 맞춰 갱신했다. |
| `./scripts/harness check` (재실행) | BASELINED | 135개 중 기존 `healthApiReturnsOk`의 HTTP 404만 남았다. 아키텍처·보안·마이그레이션·문서와 Compose smoke 검사가 통과했다. |

## 위험과 롤백

설정 조회 실패 시 현재 시도를 중단하고 다시 시도할 때 새 응답을 확인한다.
문제가 생기면 이번 Checkout 스크립트 변경만 되돌릴 수 있다.

## 미해결 항목

출시용 종단 검증은 결제 환경 PRD의 후속 범위다.

## 완료 조건

비활성 상태에서 주문 생성과 예약 요청이 차단되고, 활성 상태의 정상 결제와 예약 실패 처리를 모의 응답으로 확인한다. 결제·재고 및 로컬 CI 검사에 신규 실패가 없다.
