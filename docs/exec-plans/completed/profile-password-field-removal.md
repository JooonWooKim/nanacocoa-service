# 회원정보 수정의 현재 비밀번호 재입력 제거

상태: 완료

## 목표

회원정보 수정 폼에서 현재 비밀번호를 없애고 앞서 완료한 본인 확인으로 저장합니다.

## 하지 않는 일

진입 본인 확인과 비밀번호 변경의 현재 비밀번호 검증, 기존 UI 정렬은 유지합니다.

## 현재 증거

이전 본인 확인 기능과 UI 변경이 커밋되지 않은 상태이며 모두 보존합니다.
현재 회원정보 저장 DTO와 Service, 프런트엔드도 비밀번호를 요구하므로 함께 정리합니다.

## 결정

회원정보 저장 요청의 currentPassword를 제거하고 서버의 requireVerified를 유지합니다.
기존 잘못된 비밀번호 저장 테스트는 미확인 세션 거부 계약으로 변경하며, 비밀번호
변경에서는 잘못된 비밀번호 거부를 명시적으로 검사합니다. 테스트 식별자 2개만
변경하고 기존 실패 기준선은 수정하지 않습니다.

## 위험과 롤백

서버 확인이 없거나 만료·무효화되면 저장을 거부해야 합니다. 비밀번호를 브라우저에
보관해 대신 제출하지 않습니다. DB 변경은 없으며 이 변경만 되돌릴 수 있습니다.

## 미해결 항목

이번 변경의 미해결 항목은 없습니다. 기존 인증·상태 확인 실패 5개와 보안 부채는
기존 기준선에 남아 있습니다. 실행 중인 서버는 재빌드·재시작하지 않았습니다.

## 완료 조건

본인 확인 후 비밀번호 없는 저장 성공, 미확인·무효화 저장 거부, 비밀번호 변경의
재검증 유지, 전체 check 실행과 결과 분류, 문서 갱신 및 회귀 검토.

## 최종 리뷰

- 본인 확인 후 현재 비밀번호가 없는 요청으로 저장되는 것을 통합 테스트했습니다.
- 미확인 및 비밀번호 변경으로 무효화된 세션은 비밀번호 없는 저장도 거부합니다.
- 프로필 폼에는 비밀번호 필드가 없고 비밀번호 변경 폼에는 남아 있음을 검사했습니다.
- 기존 필수 프로필 검증, 이메일 수정 금지, 비밀번호 변경의 현재 비밀번호 검증은 유지했습니다.
- 기존 작업을 보존했으며 DB·실제 회원 데이터·외부 제공자를 변경하지 않았습니다.
