# 세션 보안 출시 준비

상태: 완료

## 목표

SEC의 토큰, 로그인, 로그아웃 및 결제 복귀 계약을 구현한다.

## 하지 않는 일

결제 제공자 환경과 반품 기능은 각각 PAY와 RETURN에서 다룬다. 스키마는 유지한다.

## 현재 증거

- [세션 보안 구현 PRD](../../product-specs/session-security-prd.md)
- 실제 HTTP 쿠키 통합 테스트, 회원·구매·운영 API 통합 테스트, Chrome 모의 결제 확인

## 결정

같은 출처의 쓰기에 전역 CSRF와 서버 세션 토큰을 사용한다. 실패한 쓰기는 다음 사용자
동작에서 새 토큰으로 제출한다. 로그인 시 컨테이너에서 세션 ID를 회전한다.

## 작업 분해

- [x] 기존 배송 CSRF와 공통 쓰기 요청 조사
- [x] 서버 계약과 화면 복구 구현
- [x] HTTP 세션 테스트와 브라우저 모의 결제 검증
- [x] 전체 하네스 검증과 변경 검토

## 진행 상황

- 2026-11-16: 기존 배송 CSRF, 공통 요청 함수, 직접 세션 인증 흐름을 확인하고 변경했다.
- 2026-11-16: 실제 HTTP 쿠키와 Chrome 모의 결제로 세션 폐기 및 로그인 복귀를 확인했다.

- 2026-11-16: 브라우저의 회원·운영·주문 쓰기 요청을 확인하고 보안 예외 3개를 해소했다.

## 명령과 증거

| 명령 | 상태 | 증거 |
| --- | --- | --- |
| `./scripts/harness test` | FAIL | 128개 중 기존 상태 확인 테스트만 HTTP 404로 실패했다. |
| 세션·회원·재고 집중 테스트 | PASS | HTTP 쿠키 회전·폐기와 승인 중복 방지를 확인했다. |
| `./scripts/harness check` | BASELINED | 문서·아키텍처·마이그레이션·보안 검사 성공. 테스트 128개 중 127개 통과, 기존 상태 확인 실패 1개, 건너뛴 테스트 0개. |
| Chrome 브라우저 모의 화면 | PASS | 가입·로그인·로그아웃, 본인 확인·프로필 수정, 이미지 업로드, 재고 변경, 주문 생성·취소. |
| Chrome 브라우저 모의 결제 | PASS | 토큰 조회 실패에서 쓰기 없이 복구. 콜백 세션 만료 후 로그인 복귀 및 같은 멱등성 키로 승인 한 번. |
| Chrome 브라우저 모의 배송 | PASS | CSRF 오류 후 입력 유지와 재시도, 출고·송장 정정·배송 완료를 확인했다. |

## 위험과 롤백

서버와 정적 클라이언트를 함께 반영하고 롤백도 같은 단위로 진행한다. 클라이언트에
캐시된 이전 스크립트가 있으면 새 리소스를 받도록 다시 로드한다.

## 미해결 항목

NC-TEST-001에 남은 상태 확인 엔드포인트는 출시 승인 전 수정한다.

평가와 문서·아키텍처·마이그레이션·보안 검사 결과를 확인했다.
