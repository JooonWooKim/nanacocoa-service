# 로컬 서비스 구매 흐름 점검 — 2026-10-24

## 판정
현재는 회원가입·로그인·상품 탐색·주문 생성이 가능한 상태입니다. 구매 완료와 배송·사후 처리를 포함한 실제 서비스 준비 완료로 판정할 수 없습니다.

기존 localhost:8080에서 가상 회원으로 직접 브라우저 테스트했습니다. 실제 개인정보, 결제 제공자, S3는 사용하지 않았습니다. 로컬 회원 1개와 CREATED 주문 1개가 남습니다.

## 직접 실행한 결과
| 단계 | 상태 | 관찰 |
| --- | --- | --- |
| 회원가입 | PASS | 가상 이메일·주소, 010-0000-0000으로 가입 후 로그인 화면 이동 |
| 로그인 | PASS | 신규 계정 로그인 후 회원 이름이 메뉴에 표시됨 |
| 상품 목록·상세 | PASS | 상품 9개, 상품 9의 이름·가격 41,000원 확인 |
| 장바구니 | FAIL | 담김 표시만 변경, 새로고침하면 초기화. 헤더 링크도 실제 장바구니 목록으로 이동하지 않음 |
| 바로 구매 | PASS | checkout 진입, 수령인 이름 자동 입력 |
| 배송 정보 | PASS | 우편번호·기본/상세주소 수동 입력 가능. 주소검색 버튼 준비 완료 확인; 검색 팝업 결과 선택은 미검증 |
| 수량·금액 | PASS | 수량 2개로 변경 시 82,000원 표시 |
| 결제 설정 조회 | PASS | 인증된 GET /api/payments/client-config가 200. 키 값은 기록하지 않음. 실제 유효성·테스트/운영 구분은 미검증 |
| 주문 생성 API | PASS | POST /api/orders 201, totalAmount 82000, status CREATED |
| 결제 승인·완료 | BLOCKED | 외부 호출 금지 범위. 브라우저 결제 버튼 제출·약관 수락·Toss 호출을 수행하지 않음 |
| 본인 확인·마이페이지 | PASS | 현재 비밀번호 확인 후 회원정보·비밀번호 변경 화면 도달. 변경 제출은 미실행 |
| 주문 내역·배송 조회 | FAIL | 마이페이지에 해당 기능이 없고 OrderController도 생성 API만 제공 |

브라우저 checkout과 API 주문 생성은 별도 검증입니다. 브라우저 구매 완료 E2E가 통과한 것으로 해석하지 않습니다.
