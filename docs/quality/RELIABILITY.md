# 신뢰성

상태: 집중 테스트 검증됨, 애플리케이션 전체 기준선에는 알려진 실패가 있음

## 핵심 불변식

- 주문 합계는 client가 보낸 금액이 아니라 저장된 상품 가격에서 계산합니다.
- 결제 시도는 소유한 주문과 안정적인 fingerprint 범위에 속합니다.
- 서로 다른 입력으로 같은 멱등성 키를 재사용하면 실패합니다.
- 주문 락을 사용할 수 없거나 경합하면 실패 우선으로 닫힙니다.
- 외부 제공자 호출과 로컬 상태 전이는 복구 가능해야 합니다.
- 확정 실패, 불확실, 보상, 승인, 취소에는 명시적 상태 전이가 있습니다.
- 복구는 권위 있는 제공자 상태와 제한된 재시도 메타데이터를 사용합니다.
- 데이터베이스와 JPA 스키마는 호환성을 유지합니다.

이 불변식은 `harness/evals/catalog.tsv`와 주문·결제·마이그레이션 집중
테스트로 표현됩니다.

## 피드백 루프

```sh
./scripts/harness test-unit
./scripts/harness eval
./scripts/harness smoke
./scripts/harness evidence
```

`smoke`는 의도적으로 스택 생명주기를 변경하지 않습니다. 전체 스택 시작은
운영자가 명시적으로 수행해야 합니다. 이 명령은 placeholder 변수와
`--env-file /dev/null`로 Compose를 검증하고, 실행 중인 Compose app의 공개
포트 또는 명시적 `HARNESS_APP_PORT`만 확인하며, 최상위 상태가 `UP`인
Actuator JSON만 통과시킵니다.

## 알려진 공백

- NC-TEST-001 때문에 애플리케이션 전체 엄격 검사가 통과하지 못합니다.
- NC-OBS-001 때문에 런타임 상관관계·metrics·tracing이 제한됩니다.
- NC-OPS-001/002 때문에 로컬 안전 `.env.example` 밖에서는 실제 제공자
  시작 기본값이 안전하지 않습니다.
- NC-DATA-002는 H2 호환 검사가 MySQL 8.4 실행 검사가 아님을 기록합니다.
- 명시적으로 실행한 Compose 스택의 증거가 아직 없습니다.

락, 멱등성 검사, 트랜잭션 경계, 복구 경로, 의미 있는 assertion을 제거하는
방식으로 신뢰성 실패를 해결하지 않습니다.
